<h2>一、三个真问题，决定这笔钱花得值不值</h2>
<h3>问题一：能不能先试用，试用期到底给多长</h3>
<p>试用不是客气话，得写进工单才算数。行业里常见的做法是给 24 到 72 小时的测试额度，或者按小时计费让你先跑两天。你要问清三件事：试用给的是不是和正式套餐同一批出口，还是从共享池里临时拨一条；试用期有没有流量上限，超了会不会直接断；试用结束配置会不会被回收，需不需要重新绑定。如果对方只肯丢一条共享地址让你 ping 一下，那基本测不出真实体验。</p>
<h3>问题二：线路掉了，多久能给换</h3>
<p>替换时效要落到小时，而不是「尽快处理」。可以这么问：工作日几点到几点有人值守，夜间掉线算不算工时，替换是同地区同类型直接换，还是要补差价升级。靠谱的服务商会要求你提供 mtr 或 traceroute 截图，用来判断是你本地网络还是出口侧的问题。这个流程本身是好事，说明他们在做归因，而不是一味甩锅。</p>
<h3>问题三：账号没过验证，钱能不能退</h3>
<p>这是争议最多的一条。多数服务商的边界是：未开通、未产生流量可以退；已消耗流量按比例折算；因为你自己账号资料和出口地区不一致导致的验证失败，通常不在退款范围。下单前把这句话问出来，让对方在工单里回一句明确的，比事后争三天有用。</p>

<h2>二、试用期该测的四项，别只看页面能不能打开</h2>

<p>能打开 claude.ai 并弹出登录框，说明不了任何问题，很多机房地址同样能打开。真正要测的是四项：出口归属、延迟抖动、丢包率、晚高峰表现。前两项十分钟能出结果，后两项得蹲时间，而恰恰是后两项决定你以后每天用得顺不顺。</p>
<h3>四项指标的测法与参考区间</h3>
<p>出口归属用 curl 请求 ipinfo.io 或 ip-api.com，看返回的 org 字段是不是本地运营商，而不是 hosting、cloud、datacenter 这类字眼，顺手在 scamalytics 一类站点查风险评分。延迟用 ping 连打一百个包，比较平均值和最大值的差距；丢包率直接看百分比。晚高峰要在当地时间的 20:00 到 23:00 之间重测一遍。跨境线路往返延迟一般在一百五十到两百五十毫秒，同城节点三十到六十毫秒，长期超过三百毫秒就要怀疑绕路。</p>

<h2>三、替换和退款条款里最容易看漏的几行</h2>
<h3>看漏点一：替换是等价换还是补差换</h3>
<p>有些套餐写着「支持替换」，实际操作时告诉你同价位的池子已经空了，只能补差价升级到高一档，或者换一个不同城市的节点。前者是变相涨价，后者会让你的出口地区和账号资料对不上。下单前问一句：替换是否保证同国家同类型同价位，池子空了怎么算。</p>
<h3>看漏点二：退款按自然日还是按已用流量折算</h3>
<p>按自然日折算，你用到第三天申请，可能只扣三天；按流量折算，一次大文件下载就能把退款额度吃掉大半。条款里通常只写「按实际使用情况」，这句话必须让对方给公式。另外注意起算点：是从付款时间算，还是从配置交付时间算，中间隔一个周末就可能差出两天的钱。</p>

<h2>四、把口头承诺落成可核对的记录</h2>
<p>付款前把四样东西存好：工单编号、聊天记录截图、套餐页面快照、发票或收据。套餐页面一定要存快照，因为页面上「不限流量」「独享出口」这类描述经常在活动结束后被悄悄改掉。用 Notion 或者一个共享表格建个简单台账，记录每月的开通日、续费日、掉线次数、替换次数，三个月后你就能算出这条线到底值不值。</p>
<p>还有一个小动作很管用：第一次和客服沟通就明确说「我会把结论记录在工单里」，多数服务商在有书面记录的情况下，处理速度和口径都会更规范。这不是施压，只是把模糊地带变成可追溯的条目。</p>

<h2>常见问答</h2>
<h3>试用期只有 24 小时，够测出东西吗？</h3>
<p>答：够测出口归属和延迟，不够测晚高峰和长稳。可以要求把试用拆成两个时段，一段放在工作日白天，一段放在当地晚间，哪怕每段只有几小时，也比连续二十四小时更有参考价值。</p>
<h3>替换次数有没有上限？</h3>
<p>答：多数套餐按自然月给次数，常见是每月一到三次，超出后按次收费。要问清次数是按账号算还是按订单算，以及替换后当月的计费是否重新起算。</p>
<h3>已经付了年费，中途不想用了能退剩余部分吗？</h3>
<p>答：年付套餐的退款政策通常比月付严格，常见是按已使用月份折算并扣除一定手续费，也有完全不退只换的。签之前把这条单独确认，别默认年付一定能按比例退。</p>
<h3>退款被拒，有什么可用的凭据？</h3>
<p>答：工单里的书面承诺、套餐页面快照、付款记录、以及你自己测出的异常数据截图，四样凑齐再沟通，成功率会明显高于只凭口头描述。</p>
